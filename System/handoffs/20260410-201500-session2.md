## What Was Done

### 2A. New ReadOnlyViewer.swift

**New file:** `src/editor/Clearly/ReadOnlyViewer.swift`

Created a standalone `NSWindowController` subclass that:
- Takes a file URL and renders markdown as HTML using `MarkdownRenderer.renderHTML()`
- Opens as a small (~500x400) non-editable window
- Has no toolbar, no buttons -- just native traffic lights (titled, closable, miniaturizable, resizable)
- Is non-modal (user can interact with main editor behind it)
- Sets `isReleasedWhenClosed = true` for automatic cleanup
- Window title = filename
- No save prompts (nothing is modified)
- Tracks open viewers in a static dictionary to avoid duplicates (brings existing to front)

Key method: `ReadOnlyViewer.open(fileURL:)` - static method that handles deduplication.

### 2B. Removed In-Viewer Switching from ContentView.swift

Removed all the complex in-place file switching code that was fighting DocumentGroup:
- `@State private var activeFileURL: URL?`
- `@State private var autoSaveTimer: Timer?`
- `effectiveFileURL` computed property
- `switchToFile(_ url: URL)` method
- `debouncedAutoSaveToActiveFile()` method
- All calls to the above

Reverted all `effectiveFileURL` references back to `fileURL`:
- `WindowFrameSaver(fileURL: fileURL)`
- `.focusedSceneValue(\.documentFileURL, fileURL)`
- `onChange(of: fileURL)` handler
- `EditorView` and `PreviewView` initializers
- `setupFileWatcher()` call

### 2C. Wired TextEditBrowser to Open Viewer

Updated the `TextEditBrowserView` callback in `ContentView.swift`:

```swift
TextEditBrowserView(model: textEditBrowser, onFileSelected: { url in
    ReadOnlyViewer.open(fileURL: url)
})
```

Now clicking a file in the TextMD browser sidebar opens it in a separate read-only viewer window instead of replacing the current document's content.
