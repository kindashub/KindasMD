### 1A. Font and Spacing -- Match TextEdit (Issue 6)

**Root cause:** TextEdit uses `Menlo-Regular` at 12pt with zero extra line spacing and zero kern. KindasMD defaults to 16pt with `lineSpacing: 3` and text color `0.878` (not white enough in dark mode).

**System TextEdit config** (from `defaults read com.apple.TextEdit`):
- `NSFont = "Menlo-Regular"`, `NSFontSize = 12`
- `NSFixedPitchFont = "Menlo-Regular"`, `NSFixedPitchFontSize = 11`
- No kern, no extra spacing

**Files and changes (ALL 6 locations where fontSize default appears):**

[Theme.swift](KindasMD/src/editor/Clearly/Theme.swift):
- `editorFontSize` fallback: the `size > 0 ? CGFloat(size) : 16` on line 11 -- change `16` to `12`
- `lineSpacing`: `3` -> `0` (line 40)
- Dark-mode `textColor`: `(0.878, 0.878, 0.878)` -> `(0.95, 0.95, 0.95)` (line 65, brighter)

[ContentView.swift](KindasMD/src/editor/Clearly/ContentView.swift) line 153:
- `@AppStorage("editorFontSize") private var fontSize: Double = 16` -> `= 12`

[ClearlyApp.swift](KindasMD/src/editor/Clearly/ClearlyApp.swift) lines 404, 424, 439:
- `@AppStorage("editorFontSize") private var fontSize: Double = 16` -> `= 12` (3 locations)

[SettingsView.swift](KindasMD/src/editor/Clearly/SettingsView.swift) line 6:
- `@AppStorage("editorFontSize") private var fontSize: Double = 16` -> `= 12`

[ScratchpadContentView.swift](KindasMD/src/editor/Clearly/ScratchpadContentView.swift) line 5:
- `@AppStorage("editorFontSize") private var fontSize: Double = 16` -> `= 12`

[EditorView.swift](KindasMD/src/editor/Clearly/EditorView.swift) line 8:
- `var fontSize: CGFloat = 16` -> `= 12` (parameter default)

[ScratchpadEditorView.swift](KindasMD/src/editor/Clearly/ScratchpadEditorView.swift) line 21:
- `var fontSize: CGFloat = 16` -> `= 12` (parameter default)

**UserDefaults migration (CRITICAL):** `@AppStorage` only uses the Swift default when no value is stored. If the app has been launched before, `editorFontSize = 16` is already in UserDefaults and the new code default of 12 is ignored. Add a one-time migration in `ClearlyApp.init()`:

```swift
private static func migrateFontSizeIfNeeded() {
    let d = UserDefaults.standard
    let key = "editorFontSize"
    guard d.object(forKey: key) != nil else { return }
    let stored = d.double(forKey: key)
    if stored == 16.0 {
        d.removeObject(forKey: key) // Lets the new default (12) take effect
    }
}
```

Call this from `init()` alongside `migrateKindasStripPrefsIfNeeded()`.

```swift
        }
        controlBarButton("doc.text", active: masterStripVisible) {
            withAnimation(.easeInOut(duration: 0.2)) { masterStripVisible.toggle() }
        }
        controlBarButton("folder", active: showTextEditBrowser) {
            withAnimation(.easeInOut(duration: 0.2)) { showTextEditBrowser.toggle() }
        }
        controlBarButton("list.bullet.indent", active: outlineState.isVisible) {
            withAnimation(.easeInOut(duration: 0.2)) { outlineState.toggle() }
        }
        controlBarButton("magnifyingglass", active: findState.isVisible) {
            findState.present()
        }

    .padding(.vertical, 4)

private func controlBarButton(_ icon: String, active: Bool, action: @escaping () -> Void) -> some View {
    Button(action: action) {
        Image(systemName: icon)
            .font(.system(size: 11))
```

## SESSION 4: TextEdit Browser In-Viewer (Issue 3)

**Goal:** When clicking a file in the TextEdit browser sidebar, load that file's content into the current editor window instead of opening a new document window.

### Why This Is Hard

KindasMD uses SwiftUI `DocumentGroup` which ties each window to an `NSDocument` instance. The `fileURL` is passed as a `let` from `DocumentGroup`'s file configuration and cannot be changed at runtime. `NSDocumentController.shared.openDocument` creates a new window by design. There is no sanctioned way to "switch" which file a `DocumentGroup` window represents.

### Approach: In-Place Content Swap with Edge Case Guards

**Strategy:** Read the file's text, replace `document.text`, track the active file URL in `@State`. Explicitly handle the 4 edge cases that arise from fighting DocumentGroup.

### Step-by-Step Implementation

**File:** [ContentView.swift](KindasMD/src/editor/Clearly/ContentView.swift)

Add state:
```swift
@State private var activeFileURL: URL?  // nil = using original DocumentGroup fileURL
```

Initialize in `init()`: `_activeFileURL = State(initialValue: nil)`

Add computed property:
```swift
private var effectiveFileURL: URL? {
    activeFileURL ?? fileURL
}
```

Replace all occurrences of `fileURL` in the body with `effectiveFileURL` (EditorView, PreviewView, FileWatcher, WindowFrameSaver, title display).

Add file-switching method:
```swift
private func switchToFile(_ url: URL) {
    // 1. Auto-save current file if dirty
    if let currentURL = effectiveFileURL {
        let currentText = document.text
        try? currentText.write(to: currentURL, atomically: true, encoding: .utf8)
    }

    // 2. Read new file
    guard let newContent = try? String(contentsOf: url, encoding: .utf8) else {
        DiagnosticLog.log("TextEditBrowser: failed to read \(url.lastPathComponent)")
        return
    }

    // 3. Switch content
    document.text = newContent
    activeFileURL = url

    // 4. Clear undo (prevent undoing into wrong file's history)
    DispatchQueue.main.async {
        NSApp.keyWindow?.firstResponder?
            .undoManager?.removeAllActions()
    }

    // 5. Update FileWatcher
    fileWatcher.watch(url, currentText: newContent)

    // 6. Update window title
    DispatchQueue.main.async {
        NSApp.keyWindow?.title = url.lastPathComponent
    }

    // 7. Re-parse outline
    outlineState.parseHeadings(from: newContent)
}
```

**File:** [TextEditBrowser.swift](KindasMD/src/editor/Clearly/TextEditBrowser.swift)

Change `TextEditBrowserModel.openFile` to use a callback:
```swift
var onFileSelected: ((URL) -> Void)?

func openFile(_ file: TextEditFile) {
    onFileSelected?(file.url)
}
```

Change `TextEditBrowserView` to accept and pass the callback:
```swift
struct TextEditBrowserView: View {
    @ObservedObject var model: TextEditBrowserModel
    var onFileSelected: ((URL) -> Void)?
    // ... in the row tap handler:
```

### Edge Case Handling (EXPLICIT)

**Edge 1: Cmd+S saves to wrong file.**
When `activeFileURL != nil` and differs from the DocumentGroup's `fileURL`, Cmd+S (via DocumentGroup) writes to the ORIGINAL file. Fix: Add an `onChange(of: document.text)` handler that auto-saves to `activeFileURL` on a debounced timer (e.g., 1 second after last edit). This is a "live save" model. The DocumentGroup's Cmd+S is harmless -- it writes the same text to the original file, which is stale but not destructive.

Alternative (simpler): Accept that Cmd+S saves to the original file. Add a note in the browser indicating "viewing: filename.md" so the user knows the distinction. This is the lowest-risk option.

**Recommended:** Go with auto-save to `activeFileURL` on text change (debounced). This matches the user's mental model: "I clicked this file, I'm editing this file."

**Edge 2: Dirty indicator (dot in close button) shows false positive.**
After switching, `DocumentGroup` thinks the document is modified (because `document.text` changed). This causes a "Save changes?" prompt on close. Since we auto-save to `activeFileURL`, the content is already saved. The prompt is about the ORIGINAL file which now has stale content. Mitigation: After switching, write the new content to the original `fileURL` as well (so both files have the same text and DocumentGroup doesn't see a diff). This is safe because the original file was auto-saved before the switch.

**Edge 3: Undo crosses file boundaries.**
Fixed by `removeAllActions()` on the undoManager after switching (see step 4 above).

**Edge 4: Window title shows original filename.**
Fixed by setting `NSApp.keyWindow?.title` after switching (see step 6 above). Note: DocumentGroup may reset the title on certain events. If this happens, add a `WindowTitleOverride` NSViewRepresentable that continuously sets the title.
