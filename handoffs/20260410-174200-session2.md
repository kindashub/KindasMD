# Session Handoff: Session 2 - Scroll Sync Rewrite

**Date:** 2026-04-10
**Session:** 2 of 5
**Commit:** bece7f0

## What Was Done

- Replaced fraction-based scroll sync with line-number-based position tracking for mode switches
- Added `ScrollPositionStore` enum to `PositionSync.swift` for stable line-based position storage
- Added `captureFirstVisibleLine()` and `restoreToLine()` methods to `EditorView.swift` Coordinator
- Wired line-based capture/restore into `EditorView.updateNSView()`:
  - Capture line position when leaving edit mode (going to preview or split)
  - Restore to saved line position when entering edit mode from preview
- Updated `PreviewView.swift` to estimate and save line position when leaving full preview
- Removed all scroll sync band-aids:
  - Deleted `scheduleScrollRestoreLeavingPreview()` method
  - Removed `suppressOutgoingScrollUntil` timing guards
  - Removed `previewFedEditorEchoIgnoreUntil` and `previewFedEditorAnchorFraction`
  - Removed `scrollRestoreGeneration` counter
  - Removed `notePreviewFedEditorScroll()` method
  - Removed SCROLL-DIAG logging calls
  - Removed echo heuristic in `computeScrollFraction()`
- Simplified `applyProgrammaticScroll()` to remove drivenByPreviewSync parameter
- ScrollBridge remains for split-mode fraction-based sync (unchanged)

## Testing Checklist for User Verification

1. Open a markdown document with 500+ lines
2. Scroll to line ~200 in edit mode
3. Switch to preview (⌘2) - verify scroll position is roughly maintained
4. Switch back to edit (⌘1) - verify you're at line ~200 (NOT at bottom)
5. Repeat at line 50, 500, end of document
6. Test split mode (⌘3) - scroll sync should still work between panes
7. Rapid mode switching 20x - verify no crash or jump
