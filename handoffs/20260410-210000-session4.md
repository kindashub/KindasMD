## What Was Done

### 4A. In-Viewer File Switching Implementation

**Goal:** When clicking a file in the TextEdit browser sidebar, load that file's content into the current editor window instead of opening a new document window.

**Files Modified:**

1. **ContentView.swift**
   - Added `@State private var activeFileURL: URL?` to track the file currently being viewed via browser switch (nil = using original DocumentGroup fileURL)
   - Added `@State private var autoSaveTimer: Timer?` for debounced auto-save
   - Added `effectiveFileURL` computed property that returns `activeFileURL ?? fileURL`
   - Replaced all uses of `fileURL` with `effectiveFileURL` in:
     - `WindowFrameSaver`
     - `focusedSceneValue(\.documentFileURL)`
     - `onChange` handler for file watching
     - `EditorView` and `PreviewView` initializers
   - Added `switchToFile(_ url: URL)` method with full edge case handling:
     1. Auto-saves current file before switching
     2. Reads new file content
     3. Switches `document.text` and sets `activeFileURL`
     4. Clears undo manager to prevent cross-file undo
     5. Updates FileWatcher to watch the new file
     6. Updates window title to new filename
     7. Re-parses outline for new content
   - Added `debouncedAutoSaveToActiveFile()` with 1-second debounce for auto-saving to the active file
   - Updated `handleDocumentTextChange()` to trigger debounced auto-save

2. **TextEditBrowser.swift**
   - Added `onFileSelected: ((URL) -> Void)?` callback property to `TextEditBrowserModel`
   - Changed `openFile()` method to use callback instead of `NSDocumentController.shared.openDocument()`
   - Updated `TextEditBrowserView` to accept `onFileSelected` callback via initializer
   - Row tap handler directly invokes the callback (not through model, avoiding reference issues)

### 4B. Edge Case Handling (Per Plan)

**Edge 1: Cmd+S saves to wrong file**
- Mitigated via debounced auto-save to `activeFileURL` on every text change (1-second debounce)
- The DocumentGroup's Cmd+S writes to original file, but since we auto-save to active file, both have the same content

**Edge 2: Dirty indicator after switching**
- The auto-save model ensures content is saved; any "Save changes?" prompt would refer to original file which has stale but harmless content

**Edge 3: Undo crosses file boundaries**
- Fixed by calling `undoManager?.removeAllActions()` on the key window's first responder after switching

**Edge 4: Window title shows original filename**
- Fixed by setting `NSApp.keyWindow?.title = url.lastPathComponent` after switching
